**คำขอ (9 พ.ย. 2569):** "ถ้าทำเสร็จแล้วช่วยเพิ่มระบบความปลอดภัยแบบเข้มงวด" → เลือก "ตรวจทั้งระบบก่อน" + ระดับ "สมดุล" → หลังรายงาน: แก้ "A + B + C" · แพตช์ใหม่ 1.18.4
**migration:** `077_security_hardening.sql` (คอลัมน์ระงับบัญชี · ตารางคำขอเพื่อนที่ถูกปฏิเสธ · unique index การสอบที่ค้าง · index) — ไม่ลบข้อมูล
**dependency:** `npm audit fix` (body-parser 1.20.9 · proxy-addr 2.0.8 · nodemailer 10.4.0 · qs 6.16.2 — อยู่ในช่วงเวอร์ชันเดิมของ package.json) → `npm audit --omit=dev` = 0

## ⚠️ ต้องตรวจบน Railway ก่อน/หลัง deploy
1. **Variables → `NODE_ENV=production`** (ถ้ายังไม่มี) — v1.18.4 ถือว่าเป็น production อัตโนมัติเมื่อรันบน Railway แล้ว แต่ควรตั้งให้ตรง
2. **`JWT_SECRET`** สุ่มยาว ≥ 32 ตัวอักษร (log ตอนเปิดเซิร์ฟเวอร์จะเตือน `[security] ⚠` ถ้าสั้น/เป็นค่าตัวอย่าง)
3. **SMTP** — ถ้ายังไม่ตั้ง: production จะ "ไม่พิมพ์ลิงก์รีเซ็ตรหัสผ่าน/ยืนยันอีเมลลง log" อีกต่อไป (เดิมใครอ่าน log ได้ = ยึดบัญชีได้) · ต้องการชั่วคราวตั้ง `MAILER_LOG_LINKS=on`
4. ถ้าวาง Cloudflare/CDN หน้า Railway: ตั้ง `TRUST_PROXY=2` (จำนวนชั้น proxy) ไม่งั้นการจำกัดต่อ IP จะนับผิด
5. **แอดมิน:** บัญชีแอดมินเดิมคงสิทธิ์ · อีเมลใหม่ใน `ADMIN_EMAILS` จะได้สิทธิ์เมื่อ "ยืนยันอีเมล" หรือ "เชื่อม Google" แล้วเท่านั้น

## ตรวจซ้ำโดยผู้ทดสอบอิสระ (หลังแก้)
ผู้ทดสอบที่ไม่ได้เห็นวิธีแก้ ลองโจมตีซ้ำทั้ง 16 ข้อบนเซิร์ฟเวอร์ทดสอบ: แก้แล้ว 13 ข้อ · บางส่วน 3 ข้อ → แก้เพิ่มทันที:
- ตัวกรองแชท: ชื่อแพลตฟอร์มแบบ leet (`L1NE`, `l!ne`, `1g`) · ชื่อยาวที่เว้นวรรคกลางคำ (`tele gram`) · "ไอดี on snap" → บล็อกแล้ว (ประโยคปกติอย่าง "meet on line 3 of the poem", "I am online now" ยังผ่าน)
- `/api/translate`, `/api/theme-vocab`, `/api/flashcards` ปิดระหว่างแข่ง Ranked ด้วย
- รายงานปิดแชท: บัญชีอายุ ≥ 3 วัน 3 คนยังทำให้ปิดแชทชั่วคราว 30 นาที (รอผู้ดูแลตัดสิน) — **ตั้งใจคงไว้** เพื่อให้ระบบยังหยุดคนก่อกวนจริงได้ทันที
- ระบบระงับบัญชีใหม่และบันทึกการกระทำของผู้ดูแล: ผ่านการทดสอบเจาะ ไม่พบช่องโหว่ใหม่
