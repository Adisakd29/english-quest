## สิ่งที่เปลี่ยน

**พลังชีวิตผู้เล่น (Raid)**
- เริ่มรอบพลัง 100 · ตอบผิด/หมดเวลา/ตอบเร็วผิดปกติ → บอสตีกลับ Phase 1/2/3 = −20/−25/−30 · ตอบถูกติดกันทุก 5 ข้อ ฟื้น +10 (ไม่เกินเต็ม)
- พลังหมด = จบรอบ ("หมดแรง!") · ดาเมจที่ทำไปนับครบ · **ไม่หัก Coin/EXP/ไอเทม/อันดับ** · เริ่มรอบใหม่ได้ทันที (นับเป็น 1 รอบของโควตาวัน)
- คำนวณที่เซิร์ฟเวอร์เท่านั้น (ค่าที่หน้าเว็บส่งมาไม่มีผล) · ส่งคำตอบซ้ำไม่โดนตีซ้ำ · บอสพัก/ถูกล้มแล้ว = ไม่ตี
- รอบยาวสูงสุด 40 ข้อ (เดิม 10) · โควตาวันละ 30 รอบเท่าเดิม
- ผู้ดูแลปรับได้ที่ ผู้ดูแล → World Raid → ค่าตั้ง: เปิด/ปิดพลังชีวิต · พลังเริ่มต้น · แรงตีแต่ละ Phase · ฟื้นพลัง · ข้อต่อรอบ (5–60)
- **ถ้าเคยบันทึก "ข้อต่อรอบ" = 10 ไว้ในค่าตั้ง** ค่านั้นยังใช้อยู่ (ค่าเริ่มต้นใหม่ 40 ใช้เฉพาะที่ไม่ได้ตั้งเอง) — ตรวจที่หน้าผู้ดูแลหลัง Deploy
- หน้าเว็บ: หมดเวลาแล้วส่งคำตอบว่างให้เอง (เดิมรอจนผู้เล่นกด) → เซิร์ฟเวอร์ตัดสิน "หมดเวลา"

**เล่นต่อเนื่องอัตโนมัติ (Raid)**
- ตอบถูก → ไปข้อถัดไปเองใน 1.4 วินาที · ตอบผิด → 3.2 วินาที (ให้เห็นคำตอบที่ถูก) · "หยุดอ่านเฉลย" = ไม่ข้ามเอง
- ครบ 40 ข้อ (ยังไม่หมดแรง) → เริ่มรอบใหม่เองใน 4 วินาที (กด "พัก" ได้) · หมดแรง = ไม่เริ่มเอง
- ซ่อนแท็บ/เปิดดูเฉลยอยู่ = รอ ไม่ข้าม · ปิดโหมดได้ (จำไว้ในเครื่อง `localStorage eq_raid_auto`)

**ชวนเพื่อนในแชทโลก + HP สดทุกที่**
- `POST /api/raid/invite` (ไม่มี body) → ข้อความแชทโลกชนิดคำเชิญ `invite_kind = 'raid'`, `invite_ref = R<เลขบอส>` (คอลัมน์มีอยู่แล้วตั้งแต่ migration 080)
  - ข้อความสร้างจากเซิร์ฟเวอร์ (ชื่อบอส + เลเวล) ไม่รับข้อความจากหน้าเว็บ · ไม่มีอีเมล/เบอร์/ตำแหน่ง
  - ใช้กติกาแชทโลกเดิมทั้งหมด (ต้องเปิดแชท · ถูกปิดแชท = ส่งไม่ได้ · จำกัดอัตรา) + ชวนได้ 1 ครั้ง/2 นาที/คน · บอสไม่ active = ชวนไม่ได้
- WebSocket `raid:hp` ส่งถึงทุกคนที่ออนไลน์ ไม่เกินทุก 2 วินาที: `{ id, level, status, hp, maxHp, phase, participants, online }` (ข้อมูลบอสสาธารณะเท่านั้น)
  → การ์ดหน้าแรก · การ์ดในแชทโลก อัปเดตเอง (ปุ่มเดิมไม่ถูกสร้างใหม่ระหว่างอัปเดต = แตะติดเสมอ)
- `online` = จำนวนคนที่อยู่ในหน้า Raid ตอนนี้ (WebSocket `raid:sub` + หน้า Raid ที่ใช้ Polling `GET /api/raid/poll?in=raid` ใน 15 วินาทีล่าสุด) · นับคนไม่ซ้ำ · หลายเครื่องรวมผ่าน NOTIFY `eq_raid` (ชนิด `presence`)
  - ชิปด้านบนหน้า Raid แสดง "N อยู่ในศึก" (เดิมแสดงจำนวนผู้ร่วมสู้สะสม) · ผู้ร่วมสู้สะสมยังอยู่ในการ์ดหน้าแรก/แท็บอันดับ

**แก้หน้าเลื่อนออกข้างบน iPhone (ปัดซ้าย/ขวา)**
- สาเหตุ: แถบบนสุด `.hud-id` ตั้ง `flex-shrink: 0` → จอ 421–470 px + ชื่อยาว + Coin หลักพัน ดันปุ่มเสียงล้นขวา ~13 px · iOS Safari ไม่เคารพ `overflow-x: hidden` บน body อย่างเดียว จึงปัดหน้าออกข้างได้
- แก้: ชื่อหดได้ (ตัด …) · `#app-shell { overflow-x: clip }` (ตัดส่วนเกินแนวนอนของเนื้อหาแอป) · `overscroll-behavior-x: none`
- ข้อควรระวัง (พบระหว่างทดสอบ): **ห้ามตั้ง overflow ที่ `html`** — จะทำให้ `body { overflow-x: hidden }` เดิมไม่ถูกส่งต่อไป viewport, body กลายเป็น scroll container และแถบบน (sticky) เลื่อนหายไปกับหน้า (ร่างแรกของแพตช์นี้พลาดจุดนี้ แก้แล้วก่อนส่ง)
- แถบที่อยู่หน้า Raid เป็น `#/raid` แล้ว (เดิมกลายเป็น `#/draw-room` จากลิงก์เก่า)

## บอสแต่ละเลเวลคนละตัว + เก่งขึ้น (เจ้าของขอ 25 พ.ย. 19:20)
- `config/raidBosses.js familyForLevel`: วนตระกูลที่มีโมเดลพร้อมทุกเลเวล — Lv1 Forest · Lv2 Inferno · Lv3 Frost · Lv4 Shadow · Lv5 Forest … (เพิ่มโมเดลใหม่ `ready: true` = เข้าวงเอง)
- ความแข็งแกร่งคิดจากเลเวล (`levelPower`) ไม่ขึ้นกับตระกูล:
  - HP พื้นฐาน = 20,000 × 1.12^(Lv−1) (เดิม Forest 15,000 × 1.07^(Lv−1)) · ส่วนที่คิดจากความเร็วล้มจริงคูณเพิ่ม ×1.12 (ตัวถัดไปแข็งกว่าตัวก่อน)
  - เกราะ (ลดดาเมจ) = 2% ต่อเลเวล สูงสุด 35%
  - แรงตีผู้เล่น = ค่า Phase × (1 + 5% ต่อเลเวล) สูงสุด ×2 · หน้าวิธีเล่นแสดงค่าจริงของบอสปัจจุบัน
  - ผู้ดูแลปรับได้ทุกค่าในหน้าตั้งค่า World Raid (บันทึก Audit Log)
- **บอสที่กำลังสู้อยู่ตอนนี้ไม่เปลี่ยน** (ตระกูล/HP/เกราะบันทึกไว้ตอนเกิด) — มีผลตั้งแต่บอสตัวถัดไป · ถ้าต้องการเปลี่ยนตัวปัจจุบันทันที ใช้ "บังคับตระกูล"/set_family ในหน้าผู้ดูแล
