# BRIEF — English for Work (เนื้อหาเฉพาะสมาชิก Premium · EnglishQuest)

ผู้เรียน: คนไทยวัยเรียน/วัยทำงาน ระดับ B1–B2 ต้องการใช้ภาษาอังกฤษในที่ทำงานจริง
งานของคุณ: เขียนไฟล์ JSON ของหัวข้อที่ได้รับมอบหมาย หัวข้อละ **12 รายการ** (ห้ามขาด ห้ามเกิน)

## หัวข้อทั้งหมด (id · รหัส · ชื่อ)
- emails · EML · อีเมลที่ทำงาน (Workplace Emails) — ขึ้นต้น/ติดตามงาน/แนบไฟล์/ขอข้อมูล/ขอโทษที่ตอบช้า/ปิดท้าย
- meetings · MTG · การประชุม (Meetings) — เปิดประชุม/ขอความเห็น/แสดงความเห็นด้วย-ไม่เห็นด้วยอย่างสุภาพ/ขอให้ชี้แจง/สรุป/มอบหมายงาน
- interview · INT · สัมภาษณ์งาน (Job Interviews) — แนะนำตัว/จุดแข็ง/จุดที่กำลังพัฒนา/ประสบการณ์/ถามกลับผู้สัมภาษณ์/ขอบคุณ
- calls · CAL · โทรศัพท์และวิดีโอคอล (Phone & Video Calls) — รับสาย/ขอสาย/ฝากข้อความ/สัญญาณไม่ดี/ขอให้พูดซ้ำ/วางสาย
- presentations · PRE · การนำเสนองาน (Presentations) — เปิดเรื่อง/บอกโครงสร้าง/อ้างอิงกราฟ/เปลี่ยนหัวข้อ/สรุป/รับคำถาม
- clients · CLI · คุยกับลูกค้าและเพื่อนร่วมงาน (Clients & Colleagues) — ทักทาย small talk/เสนอความช่วยเหลือ/รับเรื่องร้องเรียน/ขอโทษ/ขอบคุณ/นัดหมาย

## รูปแบบไฟล์ (ต้องเป็น JSON ที่ parse ได้)
```json
{
  "topic": "emails",
  "items": [
    {
      "id": "W-EML-01",
      "level": "B1",
      "register": "formal",
      "phrase": "I'm writing to follow up on",
      "th": "ขอเขียนมาเพื่อติดตามเรื่อง",
      "noteTH": "ใช้เปิดอีเมลเมื่อต้องการทวงถามหรือติดตามเรื่องที่คุยกันไว้ สุภาพและใช้ได้กับลูกค้า",
      "example": "I'm writing to follow up on our meeting last Tuesday.",
      "exampleTH": "ขอเขียนมาเพื่อติดตามเรื่องการประชุมของเราเมื่อวันอังคารที่แล้ว",
      "situation": {
        "promptTH": "คุณคุยงานกับลูกค้าไปเมื่อสัปดาห์ก่อนแล้วยังไม่มีความคืบหน้า คุณจะขึ้นต้นอีเมลว่าอะไร",
        "options": [
          "I'm writing to follow up on our discussion last week.",
          "I'm writing to complain about our discussion last week.",
          "Why didn't you answer me about last week?",
          "I'm writing to cancel our discussion last week."
        ],
        "answer": 0,
        "whyTH": "ข้อแรกเป็นการติดตามเรื่องอย่างสุภาพ · ข้อ 2 เป็นการร้องเรียน · ข้อ 3 ห้วนและฟังดูต่อว่า · ข้อ 4 เป็นการยกเลิก ไม่ใช่การติดตาม"
      },
      "cloze": {
        "sentence": "I'm writing to ___ up on our meeting last Tuesday.",
        "options": ["follow", "catch", "pick", "make"],
        "answer": 0,
        "whyTH": "follow up on = ติดตามเรื่อง · catch up on = ตามให้ทัน · pick up on = สังเกตเห็น · make up = แต่งเรื่อง/คืนดี"
      }
    }
  ]
}
```

## กฎ (validator ตรวจอัตโนมัติ + มีคนตรวจแบบไม่เห็นเฉลย)
1. `id` = `W-<รหัส>-01` … `W-<รหัส>-12` ตามลำดับ · `level` เป็น "B1" หรือ "B2" · `register` เป็น "formal" | "neutral" | "informal"
2. `phrase` = วลี/ประโยคสำเร็จรูปที่ใช้จริงในที่ทำงาน (2–10 คำ) **ห้ามมี ... หรือ … หรือวงเล็บ หรือ /** · ไม่ซ้ำกันทั้งไฟล์
3. `example` = ประโยคเต็ม 1 ประโยค (≤ 22 คำ) ขึ้นต้นตัวใหญ่ ลงท้าย . ? ! และ **ต้องมี phrase อยู่ในประโยคตรงตัว** (ไม่สนตัวพิมพ์เล็ก-ใหญ่)
4. `cloze.sentence` = `example` ที่แทนคำ **1 คำในส่วนของ phrase** ด้วย `___` (มีครั้งเดียว) · เติม `options[answer]` แล้วต้องได้ `example` เป๊ะ · ตัวเลือก 4 คำ เป็นคำเดี่ยว ไม่ซ้ำ · ตัวลวงต้อง **ผิดชัดเจนในบริบทนี้** (ไม่มีข้อที่ถูกได้สองข้อ)
5. `situation.options` = 4 ตัวเลือกภาษาอังกฤษ ไม่ซ้ำ · มีข้อที่เหมาะสมที่สุด **ข้อเดียวชัดเจน** (ตัวลวงผิดเพราะความหมาย/ความสุภาพ/บริบท — ไม่ใช่ผิดแกรมม่าเล็กน้อย) · ข้อถูกควรใช้ phrase หรือรูปแบบเดียวกับ phrase
6. **กระจายตำแหน่งคำตอบ**: ทั้ง `situation.answer` และ `cloze.answer` ในไฟล์ต้องมีครบ 0,1,2,3 และไม่มีตำแหน่งไหนเกิน 4 ครั้ง (อย่าให้ข้อถูกอยู่ข้อแรกเสมอ เหมือนตัวอย่างข้างบน)
7. ภาษาไทยเป็นธรรมชาติ ถูกต้อง ไม่มีสระลอย/ตัวอักษรแปลก · `whyTH` อธิบายทั้งข้อถูกและเหตุผลที่ตัวลวงผิด (สั้น กระชับ)
8. เขียนเอง (original) ห้ามคัดลอกจากหนังสือ/เว็บ · ไม่มีชื่อบริษัท/แบรนด์จริง ไม่มีข้อมูลส่วนตัวจริง · เนื้อหาเหมาะกับทุกวัย
9. ภาษาอังกฤษเป็นแบบที่ใช้จริงในที่ทำงานสากล (สะกดแบบ US) ถูกไวยากรณ์ 100%

ตรวจไฟล์ของคุณด้วย: `node scripts/work/validate.js data/premium/work/<topic>.json` (ต้องผ่าน 0 error ก่อนส่ง)
